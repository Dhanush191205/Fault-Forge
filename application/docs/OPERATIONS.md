# Operations and production acceptance

## Health and failure behavior

- `/api/health`: process liveness and explicit demo status.
- `/api/ready`: database connectivity and migrated schema. It does not certify NVIDIA/Chroma readiness.
- Generation jobs record queued/running/succeeded/failed state and a safe error code. No source text, provider response, password or key is placed in an API error or job audit.
- Missing or irrelevant retrieval, source permission failure, range mismatch or provider outage blocks generation. Published learning sessions continue independently of inference.
- Workers claim one job with a five-minute lease. Model timeout is bounded to 90 seconds, JSON parse repair to one retry. Expired work may be reclaimed at most three times; stale tokens cannot commit a scenario.
- Database-backed login/generation limits work across replicas. Queue capacity admission is serialized. Rate-bucket rows are operational metadata; add a scheduled retention policy for obsolete windows in the chosen deployment.
- Request IDs are generated by the server. Logs use fixed event messages plus IDs/codes. Retain audit rows according to the organization's training-record policy.

## Release and rollback

Keep application releases, schema revisions, model/embedding revisions, source checksums, prompt version and rubric version in one release manifest. Apply additive migrations. Never update published payloads or completed grades to match new code. Add new scenario/source identifiers for changes and retain old engines when transition semantics change. Retirement removes a scenario from new sessions while preserving existing attempts.

Initial DDL is frozen in `migrations/schema_v1.py`. Routine downgrade commands are intentionally disabled because dropping tables or history contradicts the requirements. Roll back application/configuration when schema compatibility allows it; otherwise restore a verified backup into a new database and reconcile records.

## Backup and restore

Back up PostgreSQL with encrypted, access-controlled backups and the selected recovery retention policy. Store any original manuals externally with immutable version/checksum references. Chroma is rebuildable from approved source rows with the pinned embedder, but keep a snapshot to shorten recovery time. The fixture database is not a production backup strategy.

Restore into an isolated environment, verify migrations, source hashes and scenario hashes, replay sampled sessions, and compare original/result counts before switching traffic. Record actual recovery time and lost-record window. No recovery objective is claimed until this exercise is measured. Do not remove a production volume as a rollback action.

## Production acceptance gates

1. Instructor acceptance of exact equipment model/revision, component ranges, procedures, case alternatives and rubric fairness.
2. Authorization for source storage, embedding and chosen inference destination. Imported content is data, never application instructions.
3. Real NVIDIA inference and embedding contract checks with nonempty retrieved context; no fixture provider in production.
4. PostgreSQL concurrency runs for worker claims, queue admission, duplicate actions/submissions, publication and rationale review.
5. Chroma tests for machine/ID scoping, semantic misses, relevance cutoff, stale checksums and outages; retrieval evaluation on case-family-held-out examples.
6. Cross-user and cross-role access tests; TLS/cookie/origin verification on the actual deployed domain; independently scoped DB runtime role and secret rotation.
7. Representative load and soak measurements for agreed learner/API and authoring concurrency; report latency percentiles and failure rates rather than claiming unlimited scale.
8. Browser tests on actual workshop devices, including WebGL failure and low-memory behavior; component-map accessibility retained.
9. Backup restoration with audit/history verification and named operators for incidents, curriculum changes and model releases.

## Known boundaries

This is a complete synthetic pilot workflow, not a certified maintenance qualification or a physics-calibrated twin. It does not control PLCs, infer remaining useful life or issue physical repair commands. It uses recorded evidence revealed through deterministic stages. Static fixture sensors are not live telemetry. Source correctness and open-ended reasoning require instructor judgment. Imported JSON packs are supported; automatic PDF/OCR ingestion and model training are intentionally not claimed.

Local credential provisioning is suitable for a private pilot. Enterprise SSO/MFA, self-service password recovery, tenant isolation and a formal grade-appeal workflow require separate integration before an enterprise rollout. No multi-tenant safety claim is made.
